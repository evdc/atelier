## Context
`TranscriptView` renders every item with `<For>`. Real sessions reach thousands of items (each tool call is one);
opening one must be instant and scrolling must hold 60 fps. Session list rows already use
`content-visibility: auto`.

## Goal
Opening a 5,000-item session paints in < 100 ms after its events arrive, and scrolling never drops frames.

## Scope
1. First, measure: add a dev-only fixture generator (e.g. `web/src/agents/fixtures.ts`) producing N realistic
   events, and a `?fixture=5000` dev route that renders a transcript from it without a server.
2. Try the cheap fix first: `content-visibility: auto; contain-intrinsic-size: auto <estimate>` on each item
   container. Measure. If it meets the goal, stop there and document the numbers in this ticket.
3. Only if needed: windowed rendering (render the visible range ± overscan, spacer elements above/below, measured
   heights cached by item id). Write it yourself (~150 lines); no library.
4. Preserve: stick-to-bottom while at the bottom, stable scroll position when items above change height, and
   jumping to the bottom on open.

## Acceptance
- [ ] Numbers recorded here: time to first paint and scroll fps for 500 / 5,000 items, before and after.
- [ ] No regression in stick-to-bottom behaviour during streaming.
- [ ] `make check` passes.

## Out of scope
Search within a transcript.

## Status (partial — not verified)
Done: `web/src/agents/fixtures.ts` + `ui/Fixture.tsx` (`http://localhost:5173/?fixture=5000`, dev only; shows
mount→paint ms); cheap fix `content-visibility: auto; contain-intrinsic-size: auto 48px` on `.tx > *`; an extra
ResizeObserver on `.tx` so stick-to-bottom survives estimated→real height changes.

Not done: the agent environment had no node/pnpm/browser, so nothing was typechecked or measured, and `make check`
was not run. Numbers (500 / 5,000 items, before/after, time-to-paint and scroll fps) still need recording: load the
fixture route with and without the `.tx > *` rule. If 5,000 misses < 100 ms, move to step 3 (windowing).
Watch for: `content-visibility` paint containment clipping overflow, and bottom landing short on open.

## Measured (user, Chrome)
content-visibility only: 500 items 48 ms, 5,000 items 370 ms mount→paint (includes fixture generation+fold, so
slightly pessimistic); INP 56 ms at 5,000. Misses the < 100 ms goal: content-visibility skips layout/paint but not
the JS that builds 5,000 components. Step 3 implemented (windowing in `Transcript.tsx`, `.it` wrappers, spacers,
height cache by id, manual scroll anchoring); re-measure and record "after" numbers. Untyped-checked: no node here.
