## Context
Tool calls render as a one-line `<details>` with JSON input and raw result (`ToolView` in
`web/src/ui/Transcript.tsx`; `summarize` in `web/src/agents/tools.ts`). Reviewing what an agent changed is the
core job of this app, so edits must read like diffs.

## Goal
Each common tool has a purpose-made view; the one-line summary stays as the collapsed state.

## Scope
- `Edit` (`old_string`/`new_string`, `replace_all`) → a unified diff of the two strings, `+`/`−` lines tinted with
  `--green`/`--red` at low alpha. Show `+N −M` counts in the summary line (as in the mockups: `Edit server/auth/limits.ts +48`).
- `Write` → the new file's content (collapsed beyond 40 lines) and its line count in the summary.
- `Bash` → command in the summary; output in a mono block, tail-truncated to the last 200 lines with "show all";
  exit status visible if the result is an error.
- `Read` → path + line range in the summary; contents not shown by default.
- `Grep`/`Glob` → match count in the summary.
- `TodoWrite` → a checklist (☐/☑, as in the mockups' `.check`).
- Everything else keeps the generic JSON view.
- Syntax highlighting for code in diffs and Write views: lazily, only when expanded, off the main thread (Web
  Worker) or with a tiny highlighter; never for > 2,000 lines. Colours from tokens only (blue keywords, red
  functions, ink-3 italic comments, green strings — see the mockup palette).
- Put the per-tool logic in `web/src/agents/tools.ts` (pure, tested) and the components in `web/src/ui/tools/`.

## Acceptance

- [x] Expanding a 1,000-line Write blocks the main thread < 16 ms. (By construction: rendered in 80-line chunks per animation frame, nothing mounted while collapsed; not profiled in a browser.)
