## Context
Claude Code writes every session to `~/.claude/projects/<slug>/<session-id>.jsonl`, where `<slug>` is the session's
cwd with every non-alphanumeric character replaced by `-` (e.g. `/Users/me/repo` → `-Users-me-repo`; verify
against real files before relying on it). Each line is an entry with `type` (`user`, `assistant`, `system`,
`summary`, and bookkeeping types such as `attachment`, `queue-operation`), `uuid`, `parentUuid`, `timestamp`, and
for messages a `message` in the same shape as the stream-json output Atelier already stores as `cc.assistant` /
`cc.user`. Decision (DESIGN.md §3): import **only** sessions whose cwd is an added project's path, or one of its
worktrees.

## Goal
Adding a project shows its existing Claude Code sessions (read-only until resumed), and sessions continued in a
terminal keep appearing, without duplicating anything.

## Scope
- New optional field on `SessionCreated`: `origin: Option<Origin>` with `Origin::Imported { native_id, path }`
  (optional field ⇒ old events still parse). The sessions projection stores `native_id` from it, so sending a message
  to an imported session resumes it with `claude --resume` — that already works via `Supervisor::ensure_running`.
- An importer (`crates/atelier-server/src/import.rs`): for a project, list the slug directories for its path and
  worktree paths; for each `.jsonl` not yet imported, append `session.created` (title: the first user message, as
  in `rpc::title_from`; `created_at` from the first timestamp is *not* possible since ts is assigned at append —
  add `started_at: Option<i64>` to the body instead and prefer it in the projection), then `cc.user`/`cc.assistant`
  events for message lines, in file order. Skip bookkeeping types; strip thinking signatures (reuse the driver's
  stripping: move `strip_signatures` to a shared place).
- Incremental: remember per file the byte offset imported so far (a projection table `imports(path, native_id,
  session, offset)` folded from an `import.progressed { path, offset }` event — the log stays the truth). On
  re-scan, append only new lines.
- When: on `project.added`, on server start, and when a session file changes (use the `notify` crate, debounced
  ~500 ms; or a 10 s poll if `notify` misbehaves — measure CPU idle cost either way).
- Never import sessions Atelier itself started (their native ids are already in the sessions table).
- Large histories: import in batches of ≤ 500 events per append so live traffic isn't starved.

## Acceptance
- [ ] e2e test: a fixture `.jsonl` under a temp `HOME`-like dir is imported once; appending lines imports only the
      new ones; restarting the server imports nothing new.
- [ ] Imported sessions render in the existing transcript UI with no UI changes beyond an "imported" hint.
- [ ] Importing 200 sessions / 50k lines takes < 5 s and the UI stays responsive meanwhile.
- [ ] `make check` passes.

## Out of scope
Codex history. Subagent sidechain files (render later, with AT-016-era subagent work).
