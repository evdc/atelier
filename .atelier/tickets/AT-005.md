## Context
`Supervisor` (`crates/atelier-server/src/supervisor.rs`) keeps one `claude` process per active session until it
exits or is stopped. Each idle CC process holds ~150–300 MB. Resuming is transparent: `ensure_running` restarts with
`--resume <native_id>` on the next message (verified working against the real CLI).

## Goal
With dozens of sessions, memory stays flat: processes that have been idle a while are stopped and come back
on demand.

## Scope
- A reaper task in the supervisor: every 30 s, stop processes whose session is `idle` (not running/waiting) and
  whose last activity is older than `ATELIER_IDLE_SECS` (default 600). Track last activity in the supervisor's
  in-memory `Proc` (update on every driver event and command) — this is runtime state, not log state.
- Stopping records `process.exited { reason: "stopped" }` as today; add an optional `detail: Option<String>` field to
  `ProcessExited` and set it to `"idle"` so the UI can say "Agent stopped while idle" quietly (or nothing at all).
- Never reap a session with pending permission requests or a running turn.

## Acceptance
- [x] Unit/e2e test with a tiny idle timeout using the fake CLI: process is reaped, the next `session.send` resumes it.
- [x] `make check` passes.

## Notes
- Done: `ATELIER_IDLE_SECS` (default 600) is `Config::idle_timeout`. The reaper runs every `min(30 s, idle)`, so a
  short test timeout is not overshot. The reaper stops only sessions whose status is `idle` with no pending requests.
  Activity is re-checked under the lock before the stop.
- Driver events and commands (`running()`) refresh `last_active`. The fake CLI's init message now reports `resumed`, so
  the e2e test checks that the second process really ran with `--resume`.
- Ordering change in `pump`: the exit is logged before the process is forgotten. A reaped process must finish exiting
  before a replacement starts (`wait_stopped`, bounded at 10 s), so the old exit can't land after the new start.
- Not done: sessions in `failed` status with a live process are not reaped (the ticket says `idle`). No UI change: the
  `detail: "idle"` is in the log, and the fold still ignores `stopped` exits.
- Not verified against the real `claude` CLI. The resume path is covered only by the fake.
