## Context
Tool results (file reads, long command output) are stored inline in `cc.user` events and shipped to every client
that opens the session, including phones. A single `Read` can be 100 KB+.

## Goal
Large payloads live out of line, content-addressed, and are fetched only when someone expands them.

## Scope
- `atelier-store`: `blobs(hash TEXT PRIMARY KEY, bytes BLOB, size INTEGER)` with `put(bytes) -> hash` (BLAKE3, hex)
  and `get(hash)`; writes go through the writer thread (same transaction as the event that references it).
- Driver/supervisor ingest: for `cc.user` `tool_result` content longer than 8 KB, replace the content with
  `{ "type": "atelier_blob", "hash", "size", "preview": <first 2 KB> }` and store the full text as a blob. Keep the
  vendor shape otherwise intact. Document the substitution in `domain.rs`.
- HTTP `GET /blob/<hash>` (token via `Authorization: Bearer`), `Cache-Control: immutable`.
- Web: the Claude adapter keeps `preview` + a `blob` reference on the tool item; the tool view fetches the blob
  when expanded.

## Acceptance
- [ ] Opening a session with 50 large reads transfers < 10% of the bytes it did before (measure, note numbers here).
- [ ] Unauthenticated `/blob` requests get 401.
- [ ] Tests for put/get dedupe and the ingest substitution. `make check` passes.
