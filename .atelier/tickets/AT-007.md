## Context
Permission cards (`web/src/ui/Ask.tsx`) offer Allow / Deny. Claude Code's `can_use_tool` request carries
`permission_suggestions` (e.g. `{"type":"addRules","rules":[{"toolName":"Bash","ruleContent":"npm test"}],
"behavior":"allow","destination":"localSettings"}`), stored verbatim in `permission.requested.raw`. CC accepts
`updatedPermissions` in an allow response to apply them.

## Goal
"Allow, and don't ask again for `npm test`" in one click; "Deny" can carry a short reason that the agent sees.

## Scope
- `PermissionDecision::Allow` gains optional `updated_permissions: Option<Value>` (pass-through); the Claude driver
  forwards it as `updatedPermissions`. Verify the exact field name against the CLI with a spike script (keep it in
  `spikes/`).
- Ask card: a secondary "Always allow …" button per suggestion, labelled from the rule (e.g. "Always allow
  `npm test` here"). Deny opens an inline one-line input (Enter sends, Esc cancels) — the reason becomes the
  deny `message`.
- Keyboard: when a card is the newest pending item, `⌘↵` allows and `⌘⌫` denies (coordinate with AT-009).

## Acceptance
- [x] Spike output saved; driver unit test covers the forwarded field.
- [ ] A suggestion applied once is not asked again in that session (manual check with the real CLI, noted here).
- [x] `make check` passes.
