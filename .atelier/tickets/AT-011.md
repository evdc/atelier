## Context
`app/src/server.rs` starts `atelierd` detached if nothing listens on 127.0.0.1:7747, finding the binary via
`ATELIER_SERVER_BIN`, next to the app executable, or `PATH`. In a release bundle nothing puts it next to the app,
and agents stop when the machine restarts.

## Goal
Installing Atelier.app gives you a server that starts at login and survives the app quitting; upgrading the app
upgrades the server.

## Scope
- Bundle `atelierd` as a Tauri sidecar (`bundle.externalBin`), built by `beforeBuildCommand`
  (`cargo build --release -p atelier-server`), named with the target triple as Tauri requires.
- macOS: on first launch, write `~/Library/LaunchAgents/sh.atelier.server.plist` (KeepAlive, RunAtLoad, logs to
  `~/.atelier/atelierd.log`, program = the bundled sidecar path) and `launchctl bootstrap gui/$UID`. If a plist exists
  but points at an older app path, rewrite and `kickstart -k`. Fall back to the current detached spawn if launchctl
  fails, and say so in the UI.
- Version check: `/health` reports the server version; if it's older than the app's, restart it via launchctl.
- Linux (for VPS use): document a systemd user unit in `docs/server.md` (no installer needed).
- A tiny "Server" section in the UI (sidebar footer click): status, version, log path, restart.

## Acceptance
- [ ] Fresh macOS user: install, launch, quit app — a session keeps running; log out/in — server is back.
- [ ] `make check` passes.
