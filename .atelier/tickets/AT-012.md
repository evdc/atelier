## Context
The server binds 127.0.0.1 and authenticates with a token from `<home>/token` (`atelier_proto::local`). The web
client reads `{url, token}` from `window.__ATELIER__`, the Vite dev define, or `localStorage["atelier.server"]`
(`web/src/lib/conn.ts: serverConfig`). The phone must reach the desktop's (or a VPS's) server over Tailscale.

## Goal
Pair a phone (or a second laptop) with a server in under a minute, securely, with no copying of secrets by hand.

## Scope
- Server: `--listen` already accepts any address. Add `ATELIER_LISTEN_TAILSCALE=1`: discover the tailnet IP
  (`tailscale ip -4`) and listen there in addition to loopback. Never bind 0.0.0.0 by default.
- Per-device tokens instead of one shared token: `device.paired { id, name, token_hash }` / `device.revoked { id }`
  events, a `devices` projection; the server checks hello tokens against it (constant-time on hashes). The local
  `<home>/token` remains as the "owner" token for the desktop app.
- Pairing: desktop shows a QR code + short code for a one-time pairing URL
  `atelier://pair?url=ws://<tailnet-ip>:7747/ws&code=<one-time>`; the new client exchanges the code (RPC
  `device.pair { code, name }`, valid 5 min, single use) for its own token and saves `{url, token}`.
  QR rendering: a small dependency-free encoder or a vetted tiny lib; justify size.
- A "Devices" list (name, last seen, revoke).
- Web: a pairing screen when `serverConfig()` is null (replace `Unconfigured.tsx`).

## Acceptance
- [ ] e2e: pair with a code, connect with the new token, revoke, connection refused.
- [ ] Codes are single-use and expire. Tokens are stored hashed server-side.
- [ ] `make check` passes.
