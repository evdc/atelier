## Context
The server binds 127.0.0.1 and authenticates with a token from `<home>/token` (`atelier_proto::local`). The web
client reads `{url, token}` from `window.__ATELIER__`, the Vite dev define, or `localStorage["atelier.server"]`
(`web/src/lib/conn.ts: serverConfig`). The phone must reach the desktop's (or a VPS's) server over Tailscale.

Tailscale is assumed to be set up separately. It already authenticates devices, so instead of a pairing flow the
server asks Tailscale who a peer is.

## Goal
Reach the server from another of your own devices over Tailscale with nothing to copy but its name.

## Scope (reduced)
- Server: `ATELIER_LISTEN_TAILSCALE=1` discovers the tailnet IPv4 (`tailscale ip -4`) and listens there too, on
  the same port as loopback. Never 0.0.0.0 by default. Retries every 30 s if Tailscale isn't up yet.
- Auth: the owner token works on every listener. On the tailnet listener only, a hello without (a valid) token is
  accepted if `tailscale whois --json <peer>` shows the peer node owned by the same user as this node
  (`tailscale status --json` → `Self.UserID`). Tagged nodes never match. Verdicts cached 60 s per peer IP; CLI
  errors fail closed (and are not cached). Loopback always needs the token. Token-less auth is refused when the
  WebSocket upgrade carries a foreign browser `Origin` (only Tauri webviews, loopback dev servers, or no origin), so
  a web page visited on a trusted phone can't drive the server. The whois check is injectable (`PeerAuth`).
- Web: a Settings panel (footer connection indicator; opens by itself on rejection; replaces `Unconfigured.tsx`
  when there's no config): address (`host`, `host:port`, or `ws://…/ws`, normalized to `ws://host:7747/ws`),
  optional token; Connect probes first, then saves to `localStorage["atelier.server"]` and reloads. With a
  host-injected server it's shown read-only, and connecting elsewhere saves an override (with a way back).

## Acceptance
- [x] e2e: token accepted; missing/wrong token rejected on loopback; trusted tailnet peer accepted without a token
  via a fake whois; untrusted peer rejected (token still works); foreign Origin can't use token-less auth.
- [x] whois/status parsing is a pure function, unit-tested on captured (anonymized) JSON, incl. tagged nodes.
- [x] `make check` passes.
