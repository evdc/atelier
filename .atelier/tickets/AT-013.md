## Context
The web UI already has a narrow layout (`@media (max-width: 760px)` in `app.css`: sidebar becomes a top strip; list
and detail become separate screens). The phone is a pure client: it pairs with a server (AT-012) and never runs
agents.

## Goal
A TestFlight-able iOS app that is pleasant for the phone's job: see what needs you, answer it, send a follow-up,
glance at progress.

## Sub-tickets
AT-012 (pairing, prerequisite) · AT-021 (iOS shell, scope 1) · AT-022 (layout + Waiting home, scopes 2–3) ·
AT-023 (device verification, TestFlight, scopes 4–5).

## Scope
1. `cargo tauri ios init` in `app/` (or a separate `app-mobile/` if desktop-only code gets in the way); the host
   skips `server::ensure_running` on mobile and reads the paired config instead.
2. Mobile layout pass: safe areas, 44 px touch targets, a bottom bar (Waiting · Projects · Sessions), the
   composer above the keyboard (`visualViewport`), swipe back from detail to list.
3. "Waiting on you" as the home screen on phone.
4. Reconnect on foreground is already handled in `Conn` (visibilitychange); verify with real backgrounding.
5. Data budget: the phone subscribes only to what is on screen (already true); check bytes on a long session after
   AT-006.

## Acceptance
- [ ] Runs on a device over Tailscale; answer a permission request from the phone while the desktop shows it
      resolve live.
