## Goal
When a session starts waiting on you (or fails) and you're not looking at it, you hear about it once.

## Scope
- Client-side, from the existing all-sessions watch (`App.tsx` → `sessions`): detect transitions into `waiting` or
  `failed` (compare with the previous row). If the document is hidden or that session isn't open, notify.
- Desktop: the Notification API inside the Tauri webview (or `tauri-plugin-notification` if the web API is not
  available in WKWebView — check). Click focuses the app and opens the session.
- Dock badge = number of waiting sessions (Tauri `set_badge_count`; desktop only).
- Coalesce: at most one notification per session per 30 s.
- Mobile push (APNs) is a separate, later ticket: it needs a relay, since the server is on a tailnet.

## Acceptance
- [ ] Manual check documented: background the app, trigger an AskUserQuestion, get exactly one notification.
- [x] `make check` passes.

## Notes
- Transitions: `web/src/lib/attention.ts` (pure, `attention.test.ts`). The first snapshot only sets the baseline, so
  sessions already waiting at launch don't notify. Archived sessions are ignored. A session counts as "open" only
  while the document is visible and its session route is on screen.
- Side effects: `web/src/lib/notify.ts`. The desktop webview gets `window.Notification` from
  `tauri-plugin-notification` (its init script replaces the global), so one code path serves desktop and the browser
  dev UI. On the phone there is no Notification API and nothing happens.
- Badge: `app/src/badge.rs` (`set_badge_count`, registered on desktop only). The web side sends only changes.
- Capability: `notification:default` added to `app/capabilities/default.json`.
- **Not done: click opens the session.** The desktop plugin does not deliver click events on macOS, so clicking the
  notification brings the app forward (macOS default) but does not navigate to the session. The `onclick` in
  `notify.ts` only fires where the webview's Notification implementation reports clicks. Follow-up: a click handler
  that works on macOS (e.g. `notify-rust`'s action callbacks, or a small native shim).
- Coalescing drops a second transition within 30 s rather than deferring it.
- Manual check (not run): with `make app` (or a bundled build) running, open a session in the app, switch to another
  window or another app, then have the agent call AskUserQuestion. Expect one notification titled with the session
  title and "Waiting for you", and the dock badge to show 1. Answer the question and confirm the badge clears. Trigger
  it again within 30 s with the same session and expect no second notification. Note that macOS may ask for
  notification permission on the first notification.
