## Context
Every app start re-downloads each opened session's events from seq 1. Watches re-snapshot (cheap). On a phone over
a tailnet, a long session could take a noticeable moment.

## Goal
Re-opening a session you've seen before paints from cache immediately, then catches up.

## Scope
- Measure first: time-to-transcript for a 2,000-event session on loopback and over a slow link (Chrome throttling).
  If < 150 ms on a "Fast 4G" profile, close this ticket with the numbers — doing less wins.
- Otherwise: IndexedDB store keyed by stream → events (bounded, LRU by stream, ~50 MB cap). `createTranscript` folds
  cached events first, then subscribes `from = lastCachedSeq + 1`. Write-behind in idle callbacks; never block
  rendering on IndexedDB.
- Invalidate everything if the server's identity changes (add a stable `server_id` to `welcome`).
