## Context
Agents sit behind `AgentDriver` (`crates/atelier-driver/src/lib.rs`): `start(spec) -> AgentHandle` with a command
channel in and `DriverEvent`s out. The Claude driver is the reference (`claude.rs`), with a fake-CLI integration
test. Vendor output is stored verbatim under the vendor's namespace and folded by a per-vendor adapter on the client
(`web/src/agents/claude.ts`, registered in `fold.ts`).

## Goal
Codex sessions work like Claude Code sessions: same session list, transcript, permission cards, interrupt, resume.

## Scope (split before starting)
1. Spike (keep it in `spikes/codex-app-server/`): drive `codex app-server` (JSON-RPC over stdio) — start a thread,
   send a turn, stream deltas, approval requests, interrupt, resume a thread. Record the message shapes like
   `spikes/claude-stream-json` did. Fall back to `codex exec --json` only if app-server can't do approvals.
2. `crates/atelier-driver/src/codex.rs` implementing `AgentDriver`, namespace `codex.*`, with a fake-CLI test.
3. `AgentKind::Codex`; server picks the driver by the session's agent (`App` holds a map of drivers);
   `session.create` takes `agent`.
4. `web/src/agents/codex.ts` adapter + tests; New-session form gets an agent picker; `.tag.codex` in blue
   (mockups: `.h.cx`).
