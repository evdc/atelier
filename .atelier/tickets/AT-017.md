## Context
A session's title is the first line of the first prompt (`rpc::title_from`), which is often a poor title. The
`session.renamed` event and its projection handling already exist; there's no RPC or UI for it.

## Scope
- RPC `session.rename { session, title }` → appends `session.renamed`.
- Click the title in the session header to edit inline (Enter saves, Esc cancels).
- Agent-written titles: after the first turn ends, if the user hasn't renamed it, ask for a title *without*
  disturbing the session. Cheapest route: a one-shot `claude -p --model haiku --no-session-persistence
  --output-format json` with the first prompt and the first reply (truncated), asking for ≤ 6 words. Run it in the
  supervisor in the background; append `session.renamed` with actor `atelier`. Make it opt-out via env var.

## Acceptance
- [x] e2e test for rename. Auto-title covered by a unit test of the prompt/parse function (no network in tests).
- [x] `make check` passes.

## Notes
- Built: `session.rename` RPC (trimmed, non-empty, at most 200 chars); inline rename in the session header (Enter
  saves, Escape cancels, leaving the field cancels); `autotitle` module with `prompt`/`parse`/one-shot runner,
  started by the supervisor after a session's first successful turn, unless the stream already has a
  `session.renamed` (checked again before the title is written). Opt out with `ATELIER_AUTO_TITLE=0`.
- Tests: e2e `session_rename_over_websocket` and `auto_title_names_session_after_first_turn` (the fake CLI answers
  the one-shot titler with a fixed title, so no network is used); unit tests for prompt, parse and text extraction.
- Not verified against the real CLI: the one-shot flags (`--model haiku --no-session-persistence --output-format
  json`) were taken from the ticket and only exercised through the fake. Check the output shape on a real run.
- Not covered by a test: a rename that lands while the titler is running is respected by the re-check, but the
  check and the append are not one transaction, so a rename in that gap could still be overwritten.
- A rename (or auto-title) bumps `updated_at`, so the session moves to the top of its project's list.
- Not checked in a browser; only `tsc` and vitest were run on the web side.
- `session_lifecycle_over_websocket` failed once under load: it waited for the `alive == false` row, which can
  arrive before the `process.exited` event it then asserted on. It now waits for the event itself.
