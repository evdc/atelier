## Context
Adding a project means typing an absolute path on the server (`ProjectsView.tsx`). The server may be remote, so a
native file dialog on the client is wrong.

## Scope
- RPC `fs.list { path? }` → `{ path, parent, entries: [{ name, is_dir, is_git }] }`, directories only, hidden ones
  excluded unless asked, capped at 500 entries; default path = server user's home. A read-only computed result
  (like AT-010's `session.changes`).
- An inline picker under the path field: breadcrumb + directory list; git repos marked; "Add this folder".
- Suggestions: recently modified git repos under `~/Projects`, `~/src`, `~/code` (if they exist), max 8.

## Acceptance
- [x] Unit test for `fs.list` (temp dir tree). `make check` passes.

## Notes
- `fs.list` takes an extra optional `hidden` flag (the "hidden ones excluded unless asked" part); it's a
  `Call` param, so the result shape is as specified.
- Suggestions are a separate computed RPC, `fs.suggest {}` → `{ entries: [{ path, name }] }`, rather than a field on
  `fs.list`, so the listing shape stays as specified.
- Suggestions look one level under each root (`~/Projects/<repo>`), not recursively, to keep the walk bounded.
  Nested layouts like `~/Projects/<org>/<repo>` won't appear; follow-up if wanted.
- "Recently modified" is the mtime of `.git/index` (falling back to `.git` for worktrees), a proxy for recent activity.
- `is_git` is a `.git` existence check, not a `git` process per entry.
- The 500 cap is silent in the protocol; the picker shows "Showing the first 500 folders" when it's hit. A
  `truncated` flag would be cleaner if the cap ever matters.
- The picker is not exercised in a browser or the desktop app yet; verified by unit tests, `tsc`, and clippy only.
