## Context
`app/` is the Tauri v2 desktop host (`app/src/main.rs`, `app/src/server.rs`). On launch it calls
`server::ensure_running()` (spawns `atelierd`) and injects `window.__ATELIER__ = {url, token}`. On a phone there is
no server to spawn: the phone is a pure client. The web UI already falls back to `localStorage["atelier.server"]`
(`web/src/lib/conn.ts: serverConfig`), which the pairing screen (AT-012) writes.

Toolchain on this machine: Xcode 26.5, tauri-cli 2.12.1, rust targets `aarch64-apple-ios`, `aarch64-apple-ios-sim`.

## Goal
`cargo tauri ios build` / `ios dev` produces an app that launches in the simulator and shows the web UI, connecting
via the stored/paired config.

## Scope
- `cargo tauri ios init` in `app/` (prefer the same crate; only split into `app-mobile/` if desktop-only code gets in
  the way — say why). Commit the generated `app/gen/apple` project except build products (gitignore them).
  Tauri mobile needs a `lib.rs` with `#[cfg_attr(mobile, tauri::mobile_entry_point)] pub fn run()`; `main.rs` calls it.
- `server.rs` is desktop-only (`#[cfg(desktop)]`). On mobile, inject nothing (or only `ATELIER_URL`/`ATELIER_TOKEN` if
  set at build time for dev) and let the web UI use its stored config.
- Window: no fixed `inner_size` on mobile; full-screen webview, `viewport-fit=cover` already or add it in
  `web/index.html` so CSS `env(safe-area-inset-*)` works (AT-022 uses it).
- Networking: the webview must open `ws://100.x.y.z:7747/ws` (tailnet, cleartext). Set the needed ATS keys in the iOS
  Info.plist (`NSAppTransportSecurity` → `NSAllowsArbitraryLoadsInWebContent` and/or `NSAllowsLocalNetworking`;
  use the narrowest that works and comment why). Check the CSP in `tauri.conf.json` still allows it.
- Bundle identifier for iOS: `sh.atelier.app` (desktop keeps `sh.atelier.desktop` if a per-platform override is
  possible; otherwise note the trade-off). Leave the development team unset — signing is the user's to configure.
- Makefile targets: `make ios-dev` (simulator) and `make ios-build`.
- Desktop must keep working exactly as before (`make app`).

## Acceptance
- [ ] `cargo tauri ios build --target aarch64-sim` (or the equivalent debug build for the simulator) succeeds.
- [ ] App launches in an iOS simulator and shows the web UI (the unconfigured/pairing screen is fine). Screenshot it
      with `xcrun simctl io booted screenshot` and include the path in your hand-back.
- [ ] With `localStorage` set to a local dev server (`make dev`), the simulator connects and lists sessions.
- [ ] `make check` passes; desktop `cargo build -p atelier-app` still works.

## Out of scope
Layout changes (AT-022), pairing UI/server (AT-012), signing/TestFlight upload (needs the user's Apple account).
