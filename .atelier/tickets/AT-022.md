## Context
The web UI has a narrow layout (`@media (max-width: 760px)` in `web/src/styles/app.css`: sidebar becomes a top strip;
list and detail become separate screens). Shell is `web/src/ui/App.tsx`; routes in `web/src/lib/router.ts`; sessions
come from the all-sessions watch (`sessions` in context). Read `CLAUDE.md` rules 4 and 5 (performance, design
language) before starting.

## Goal
On a phone-sized viewport the UI is pleasant for the phone's job: see what needs you, answer it, send a follow-up,
glance at progress.

## Scope
- Safe areas: `env(safe-area-inset-*)` padding for top bar, bottom bar and composer (`viewport-fit=cover` in
  `web/index.html` if missing).
- Touch targets ≥ 44 px on narrow layout (buttons, list rows, ask/permission actions).
- Bottom bar on narrow layout: **Waiting · Projects · Sessions** (replaces the top strip). Hairline top border, tokens
  only; red count badge on Waiting when > 0.
- "Waiting on you" view: all sessions across projects whose status is waiting (and failed, below them), newest first;
  tapping opens the session. It is the default route on narrow viewports. Add it as a route; on desktop it may be
  reachable but needn't be prominent.
- Composer above the keyboard: use `visualViewport` (resize/scroll) to keep the composer pinned above the on-screen
  keyboard; no layout jank, rAF-batched.
- Swipe back from detail to list: edge swipe (from the left ~20 px) on the detail screen navigates back. Pointer
  events, no dependency; ignore when the gesture is mostly vertical.
- Don't break the desktop layout. Check both light and dark.

## Acceptance
- [x] In a 390×844 viewport (Chrome devtools / Playwright), Waiting is the home screen, bottom bar works, a waiting
      session can be opened and its permission request answered with a tap.
- [x] Composer stays visible when focusing it (emulate with a resized `visualViewport` if you can't on real keyboard).
- [x] Desktop layout unchanged at 1280×820.
- [x] Pure logic (e.g. waiting-list selection/sorting, swipe classification) has vitest tests.
- [x] `make check` and `make test` pass; bundle size increase noted in hand-back.

## Out of scope

## Notes (hand-back)
- Bottom bar tabs are Waiting (`#/waiting`), Projects (`#/`), Sessions (`#/sessions`, every session across projects).
  A session opened from a tab keeps that tab lit. Only a launch with *no* hash on a narrow viewport lands on Waiting.
- Back (edge swipe, or the ‹ button in the narrow session header) uses history when there is an in-app entry to go
  back to (depth kept in `history.state`), else the owning list.
- While the keyboard is up (`html.kb`), the footer and bottom bar hide so the composer sits on the keyboard.
- Bundle: JS 34.71 → 36.50 KB gz, CSS 4.73 → 5.16 KB gz.
- Verified in Playwright (Chromium) at 390×844 with an emulated `visualViewport`; not yet on a real iOS keyboard
  (AT-023).
