## Context
There is no way to find an old session except scrolling the list. Titles are often poor (AT-017 helps), and what
you remember is usually something said *inside* the session ("the one where we fixed the WAL checkpoint").

Search is split in two. This ticket is the lexical half: an SQLite FTS5 index kept as an ordinary projection, a
`search.query` RPC, and a search screen. AT-025 adds semantic recall on top and fuses the two; build the result
types here so that it only has to add a second ranked list.

FTS5 is already compiled into the bundled SQLite (`libsqlite3-sys` builds with `-DSQLITE_ENABLE_FTS5`), so no new
dependency is needed.

Read first:
- `crates/atelier-store/src/projection.rs`: the `Projection` trait (deterministic, same transaction as the append).
- `crates/atelier-server/src/views/sessions.rs` and `views/mod.rs`: how a projection is written and registered.
- `crates/atelier-server/src/rpc.rs`: handlers. Note the documented exceptions for read-only RPCs that return
  results directly; search is another one.
- `crates/atelier-proto/src/lib.rs`: `Call`, row types (`make gen` after editing).
- `web/src/agents/claude.ts`: how `cc.assistant` / `cc.user` bodies are read (content blocks, `parent_tool_use_id`).
- `web/src/lib/routes.ts`, `web/src/ui/Sidebar.tsx`, `web/src/ui/SessionRowLink.tsx`.

## Goal
Type a few words, see the sessions that mention them across all projects (or the current one), best first, with
a snippet of the matching text. Click one to open it.

## Scope

### What gets indexed (one document per event)
| Source | Indexed text | Column |
|---|---|---|
| `session.created` | `title` | `title` |
| `session.renamed` | `title` (replaces the previous title document of that session) | `title` |
| `user.message` | `text` | `body` |
| `cc.assistant` | `text` blocks of `message.content`, joined with blank lines | `body` |
| `cc.assistant` | `tool_use` blocks, one compact line each: `name` + the first present of `file_path`, `path`, `command`, `pattern`, `url`, `description`, capped at 200 chars | `body` |

Not indexed: tool results (`tool_result` blocks in `cc.user`), `thinking` blocks, `cc.system`, `cc.result`, and any
message with a non-null `parent_tool_use_id` (sub-agent chatter). Skip documents that end up empty. Cap a
document's text at 32 KB (cut at a char boundary). Tool results are the bulk of the log and mostly noise for
"which session was it"; tool-use lines keep "which session touched `store/writer.rs`" findable.

### Projection `search` (`crates/atelier-server/src/views/search.rs`)
```sql
CREATE VIRTUAL TABLE IF NOT EXISTS search_fts USING fts5(
  title, body,
  session UNINDEXED, project UNINDEXED, role UNINDEXED,   -- role: title | user | agent | tool
  tokenize = 'porter unicode61 remove_diacritics 2',
  prefix = '2 3'
);
-- rowid = seq of the source event. The one title document per session is tracked here so a rename can
-- delete it by rowid (FTS5 can't filter UNINDEXED columns without a full scan).
CREATE TABLE IF NOT EXISTS search_titles (session TEXT PRIMARY KEY, rowid INTEGER NOT NULL) STRICT;
```
- Bail early on kinds it doesn't index (most events), like `Sessions::apply` does.
- Session/project come from `stream::parse_session(&ev.stream)`. Read only the fields needed from vendor bodies
  with `parse_raw` into small local structs; tolerate missing fields.
- Push no `Change`s: search is not a watched view.
- `reset` drops both tables. Register in `views::projections()`. Version 1.

### Query (`views::search::query`)
- Turn user input into a safe FTS5 query: split on whitespace, drop FTS syntax characters, wrap each term in
  double quotes (doubling inner quotes), AND them together, and make the last term a prefix (`"wal"*`) so results
  appear as you type. Empty input returns nothing. Never pass raw input to `MATCH`.
- Rank with `bm25(search_fts, 4.0, 1.0)` (a title hit counts four times a body hit). Take the top 200 documents,
  optionally `WHERE project = ?`, then group in Rust by session: a session's score is its best document's score;
  keep its best hit's snippet and a hit count. Return the top `limit` sessions (default 30, max 100).
- Snippet: `snippet(search_fts, -1, '\u{2}', '\u{3}', '…', 12)`; the client turns the control characters into
  `<mark>`. Never send HTML from the server.
- Join `sessions` for the current title, archived flag and `updated_at`; drop hits whose session no longer exists.
  Archived sessions are included and flagged.

### Wire (`atelier-proto`)
```rust
/// Search sessions by what was said in them. Result: Vec<SearchHit>, best first.
#[serde(rename = "search.query")]
SearchQuery { q: String, #[serde(default)] #[ts(optional)] project: Option<ProjectId>,
              #[serde(default)] #[ts(optional)] limit: Option<u32> },

pub struct SearchHit {
    pub session: SessionId, pub project: ProjectId, pub title: String, pub archived: bool,
    pub updated_at: i64,
    pub seq: Seq,          // the best-matching event
    pub role: String,      // title | user | agent | tool
    pub snippet: String,   // \u{2}…\u{3} mark the matched terms
    pub hits: u32,         // matching documents in this session (of the top 200)
    pub score: f64,        // higher is better (negate bm25); only comparable within one result list
}
```
Add `search.query` to the list of read-only exceptions in `rpc.rs`'s module comment. Run it via `app.store.read`.

### UI
- Route `#/search?q=…` (scoped to a project when reached from one: `#/p/<project>/search?q=…`). Add to
  `routes.ts` with tests in the existing routes tests.
- A search field at the top of the sidebar (`⌘F` focuses it on desktop if it doesn't fight the browser's own find
  inside a transcript; otherwise no shortcut — AT-009 owns the palette). Typing navigates to the search route.
- Results: debounce 150 ms, drop out-of-order responses (keep the latest request id), reuse `SessionRowLink`
  styling, snippet below the title with `<mark>` in gold (things to notice). Show which project each hit is in when
  unscoped. Clicking opens the session. Empty state: "Nothing matches." in the usual muted style.
- Phone layout: the field sits above the list on the search screen; no sidebar field.

## Acceptance
- [ ] Unit tests (`views/search.rs`): fold a handful of events through the projection on an in-memory DB and
      check: user/assistant text and tool-use lines are found; tool results and thinking are not; a rename replaces
      the old title (old title no longer matches, new one does); prefix match on the last term; title hits outrank
      body hits; `project` scoping; malicious input (`"`, `*`, `NEAR(`, `OR`, `-`) doesn't error.
- [ ] e2e test in `crates/atelier-server/tests/e2e.rs`: create a session with the fake CLI, `search.query` for a
      word from its reply, get that session back.
- [ ] vitest for the query-id/out-of-order guard if it lives in a pure helper, and for routes.
- [ ] Checked in the browser on a dev home with real sessions: results appear while typing without jank.
- [ ] Index size noted in the hand-back (`SELECT SUM(pgsize) FROM dbstat WHERE name LIKE 'search_fts%'` vs the
      events table) for a real `~/.atelier-dev` log.
- [ ] `make check` and `make test` pass.

## Out of scope / follow-ups
- Semantic search and hybrid ranking: AT-025.
- Scrolling the transcript to the matching message: transcript items don't carry their event's `seq` yet. The hit
  already returns `seq`, so this is a small follow-up (`?at=<seq>` on the session route).
- Search inside one transcript (AT-002 note) and the `⌘K` palette (AT-009).
- Imported history (AT-004): if import writes the same `cc.*` / `user.message` kinds it's indexed for free; if it
  invents new kinds, the projection must learn them (bump the version).
- Blob store (AT-006): if large assistant text moves to `blobs`, the projection must resolve the hash from the same
  DB (it's in the same transaction, so that stays deterministic).
