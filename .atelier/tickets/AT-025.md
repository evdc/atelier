## Context
AT-024 indexes session text in FTS5 and ranks with BM25. That finds what you remember *word for word*. This ticket
adds recall by meaning ("the session about flaky reconnects" → one that only says "WebSocket drops after sleep"),
then fuses the two rankings so `search.query` keeps the same RPC and result type.

Embeddings can't be a projection: projections run on the writer thread inside the append transaction, and
embedding would stall appends and load a model from disk. So the vector index is a **derived cache** kept by a
background task: disposable, rebuildable from the FTS documents, never the truth. That is within the rules (the log
is still the only truth), but say so in `DESIGN.md` §5 in one sentence.

Read first: AT-024 and its code (`views/search.rs`), `crates/atelier-store/src/lib.rs` (`subscribe`, `read`),
`crates/atelier-server/src/lib.rs` (how background tasks like the supervisor are started), `autotitle.rs` (an
opt-out background job with an env var).

## Decision needed before starting: the embedder
Pick one and record it in the ticket notes. Recommended: **model2vec static embeddings** (`potion-base-8M`,
256 dims) via the `model2vec-rs` crate. A static model is a token-embedding lookup and a mean, so embedding a chunk
costs microseconds on the CPU, it needs no ONNX runtime or GPU, and the model is about 30 MB. Its retrieval quality
is below a transformer such as `bge-small` but adequate as the second signal in a hybrid. Check the crate's current
API, dependency weight and licence before adding it. If it pulls in more than `tokenizers` + `safetensors` +
small crates, stop and report.

Alternatives, if the recommendation doesn't hold up: `fastembed` (ONNX, bge-small, better quality, adds the
onnxruntime dylib to the app bundle); or a hosted embeddings API. Don't pick the API without asking: it sends
transcript text off the machine and needs a key.

Whatever is picked sits behind a trait so that tests use a fake:
```rust
pub trait Embedder: Send + Sync + 'static {
    fn id(&self) -> &str;                       // model name + version; stored with every vector
    fn dims(&self) -> usize;
    fn embed(&self, texts: &[&str]) -> anyhow::Result<Vec<Vec<f32>>>;   // L2-normalized
}
```

## Scope

### Vector cache (`crates/atelier-server/src/search_vec.rs`)
- Its own SQLite file `<home>/search-vec.db`, owned by the indexer task, so it never contends with the log
  writer. Deleting the file is a valid way to rebuild.
  ```sql
  chunks(doc INTEGER NOT NULL,        -- search_fts rowid (= event seq)
         ord INTEGER NOT NULL,        -- chunk index within the doc
         session TEXT NOT NULL, project TEXT NOT NULL,
         vec BLOB NOT NULL,           -- dims × f32, little-endian, normalized
         PRIMARY KEY (doc, ord)) STRICT;
  meta(key TEXT PRIMARY KEY, value TEXT) STRICT;  -- embedder id, cursor (last indexed doc rowid)
  ```
  If the stored embedder id differs from the current one, drop everything and start over.
- **Indexer task**: on start and after each store commit (`store.subscribe()`, coalesced so a burst triggers one
  pass), read FTS documents with `rowid > cursor` from the main DB (`store.read`) in batches of 64, chunk, embed
  on a blocking thread (`spawn_blocking`), write, advance the cursor. Titles are embedded too. A renamed title's
  old document disappears from FTS; remove orphaned chunks lazily (at query time, ignore chunks whose doc isn't in
  FTS; sweep orphans once at startup).
- Chunking: about 1,200 chars per chunk with 200 chars of overlap, cut at whitespace. Most messages are one chunk.
- In memory: load all vectors once at startup into a flat `Vec<f32>` plus a parallel `Vec<(doc, session, project)>`,
  and append as the indexer adds. Brute-force dot product; no ANN index or vector extension. Budget: 50k chunks ×
  256 dims × 4 B = 51 MB, and a scan under 15 ms. Log a warning above 50k chunks; quantizing to i8 is the
  follow-up.
- Opt out with `ATELIER_SEMANTIC_SEARCH=0` (no model load, no task, lexical only). Also off when the model can't be
  loaded. Log once, don't fail startup.
- Model files: let the crate fetch them into `<home>/models/` on first enable. Never fetch in tests or CI.

### Hybrid ranking (in `views::search` / the RPC handler)
- Lexical: AT-024's top 200 documents. Semantic: embed the query, top 200 chunks by cosine, reduced to documents
  (best chunk per doc). Drop semantic hits below a cosine floor (start at 0.25; tune by eye and record the value).
- Fuse with Reciprocal Rank Fusion at the document level: `score = Σ 1 / (60 + rank)` over the lists a doc appears
  in, ×1.5 when the doc is a title. Then group by session as AT-024 does.
- Snippet: lexical hits keep the FTS5 snippet. A semantic-only hit has no matched terms, so its snippet is the
  first ~160 chars of the best chunk, unmarked (read the doc text from `search_fts` by rowid).
- Queries of one or two characters are lexical only (the prefix match is what you want while typing).
- Add `semantic: bool` to `SearchHit` (true if the semantic list contributed), so the UI can show a quiet "related"
  marker on semantic-only hits instead of highlighted terms.
- Freshness: semantic results lag new messages by one indexer pass. That's fine; lexical covers the gap.

## Acceptance
- [ ] Unit tests with a fake `Embedder` (e.g. a bag of hashed words → fixed vectors, deterministic): chunking at
      boundaries; cursor resumes after restart; embedder id change rebuilds; RRF ordering on hand-built ranked
      lists; a semantic-only hit gets an unmarked snippet; orphaned title chunks are ignored.
- [ ] e2e: with the fake embedder injected (config hook or env), a session found only through the semantic list
      comes back from `search.query`; with `ATELIER_SEMANTIC_SEARCH=0` the result equals AT-024's.
- [ ] Hand-back reports, on a real dev log: index build time, `search-vec.db` size, chunk count, p50/p95
      `search.query` latency, and three example queries where the hybrid beats lexical (or an honest note that it
      doesn't).
- [ ] App bundle size before and after, if the embedder adds a native library.
- [ ] `make check` and `make test` pass. CI does not download a model.

## Out of scope
- Re-ranking with an LLM or a cross-encoder.
- Embedding tool results or thinking (same exclusions as AT-024).
- ANN indexes, `sqlite-vec`, quantization; revisit past 50k chunks.
- Semantic search from the phone over a slow link beyond what `search.query` already returns.
