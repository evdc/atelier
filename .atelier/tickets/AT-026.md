## Context
DESIGN §11 has agents finding, reading, messaging and spawning other sessions through an Atelier MCP server. That
server doesn't exist yet. This ticket builds it with two read-only tools, so later tickets only add tools. §10.7
(automations) will use the same server.

Read first: DESIGN §4, §10.5 ("Required refactor"), §10.7 and §11. Then `crates/atelier-server/src/rpc.rs`,
`supervisor.rs` (`send`, `ensure_running`, `pending`), `lib.rs` (the axum router), and
`crates/atelier-driver/src/claude.rs` (`command`). Also `crates/atelier-core/src/event.rs` (`Actor`) and the fake
CLI `crates/atelier-driver/tests/fixtures/fake-claude.sh`.

## Spike first (half an hour, real CLI; write the findings in Notes)

   - does it connect alongside the user's own MCP servers;
   - do tools show as `mcp__atelier__<name>`.
2. `--allowedTools mcp__atelier__sessions` under `--permission-mode auto`: no prompt?
3. What happens to a `tools/call` that takes 10 minutes:
   - does CC time out (`MCP_TOOL_TIMEOUT`)?

   AT-030's `ask` depends on this.
4. CC's own `SendMessage`/`ListAgents` (see the init message in `spikes/at-007-updated-permissions/output.jsonl`):
   - what do they reach;
   - does `--disallowedTools SendMessage,ListAgents` remove them?

   Recommend whether Atelier sessions should drop them (DESIGN §12).
5. `--append-system-prompt` still works together with stream-json input.

## Scope
- **`rpc::handle(app, actor, cause, call)`**. Today it hard-codes `Actor::User`.
  - Thread `actor`/`cause` through to every append.
  - Add `Call::agent_allowed(&self) -> bool`; `project.remove` and the fs browsing calls are user-only.
  - This is also step 2 of §10.10; if automations got there first, reuse their work.
- **Endpoint**: `POST /mcp` on the existing axum server, **loopback listener only** (never the tailnet one).
  - Minimal MCP over streamable HTTP with plain JSON responses (no SSE): `initialize`, `notifications/initialized`,
    `ping`, `tools/list`, `tools/call`.
  - Hand-rolled JSON-RPC, about 150 lines. Check `rmcp` first, but don't add it unless it's small.
- **Identity**.
  - On each agent process start, the supervisor mints a random token and keeps `token → SessionId` in memory. The
    token lives as long as the process; a resume mints a new one. It's ephemeral, so it's not logged.
  - Pass it to the process through `--mcp-config`. A request with an unknown token gets a 401.
  - Tool calls run as `Actor::Agent(session)`.
- **Driver**:
  - `StartSpec` gains `mcp: Option<McpEndpoint { url, token }>` and `system_append: Option<String>`.
  - Claude builds `--mcp-config`, `--allowedTools mcp__atelier__sessions,mcp__atelier__read`, and
    `--append-system-prompt`.
  - The appended prompt is short:
    - which session you are (id, title), and that other sessions exist;
    - prefer finding one that already knows over re-deriving;
    - tools come from `atelier`.

    Keep it under 600 chars and as a const with a test.
- **Tool `sessions { project?, status?, include_archived? }`**: one text line per session, `id · title · status ·
  branch · updated (relative) · parent?`, with your own row marked `(you)`. Defaults: your project, not archived, at
  most 50 rows. Tool output is text for the model, not JSON.
- **Tool `read { session, around?: seq, before?: seq, max_chars? }`**: a text rendering of the transcript, newest
  last, each line `#<seq> <role>: <text>`.
  - Roles and extraction are exactly AT-024's documents: user, agent text, compact tool-use lines; no tool results
    or thinking. Put the extractor in `views/text.rs` so AT-024's projection reuses it (or reuse AT-024's if it
    landed first).
  - `max_chars` defaults to 8,000 (max 32,000), cut at document boundaries.
  - Says "(N earlier — read with before=<seq>)" when cut.
  - Reads go through `app.store.read`, bounded by a seq range, never a whole stream.
- Fake CLI: when started with `--mcp-config`, a prompt containing `MCP:<tool>:<json-args>` makes it `curl` the
  endpoint (URL and token parsed from the config arg). It prints the result as a `tool_result` in a `cc.user` event
  so e2e tests can assert on it.
