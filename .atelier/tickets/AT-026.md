## Context
DESIGN §11 has agents finding, reading, messaging and spawning other sessions through an Atelier MCP server. That
server doesn't exist yet. This ticket builds it with two read-only tools, so later tickets only add tools. §10.7
(automations) will use the same server.

Read first: DESIGN §4, §10.5 ("Required refactor"), §10.7 and §11. Then `crates/atelier-server/src/rpc.rs`,
`supervisor.rs` (`send`, `ensure_running`, `pending`), `lib.rs` (the axum router), and
`crates/atelier-driver/src/claude.rs` (`command`). Also `crates/atelier-core/src/event.rs` (`Actor`) and the fake
CLI `crates/atelier-driver/tests/fixtures/fake-claude.sh`.

## Scope
- **`rpc::handle(app, actor, cause, call)`**. Today it hard-codes `Actor::User`.
  - Thread `actor`/`cause` through to every append.
  - Add `Call::agent_allowed(&self) -> bool`; `project.remove` and the fs browsing calls are user-only.
  - This is also step 2 of §10.10; if automations got there first, reuse their work.
- **Endpoint**: `POST /mcp` on the existing axum server, **loopback listener only** (never the tailnet one).
  - Minimal MCP over streamable HTTP with plain JSON responses (no SSE): `initialize`, `notifications/initialized`,
    `ping`, `tools/list`, `tools/call`.
  - Hand-rolled JSON-RPC, about 150 lines. Check `rmcp` first, but don't add it unless it's small.
- **Identity**.
  - On each agent process start, the supervisor mints a random token and keeps `token → SessionId` in memory. The
    token lives as long as the process; a resume mints a new one. It's ephemeral, so it's not logged.
  - Pass it to the process through `--mcp-config`. A request with an unknown token gets a 401.
  - Tool calls run as `Actor::Agent(session)`.
- **Driver**:
  - `StartSpec` gains `mcp: Option<McpEndpoint { url, token }>` and `system_append: Option<String>`.
  - Claude builds `--mcp-config`, `--allowedTools mcp__atelier__sessions,mcp__atelier__read`, and
    `--append-system-prompt`.
  - The appended prompt is short:
    - which session you are (id, title), and that other sessions exist;
    - prefer finding one that already knows over re-deriving;
    - tools come from `atelier`.

    Keep it under 600 chars and as a const with a test.
- **Tool `sessions { project?, status?, include_archived? }`**: one text line per session, `id · title · status ·
  branch · updated (relative) · parent?`, with your own row marked `(you)`. Defaults: your project, not archived, at
  most 50 rows. Tool output is text for the model, not JSON.
- **Tool `read { session, around?: seq, before?: seq, max_chars? }`**: a text rendering of the transcript, newest
  last, each line `#<seq> <role>: <text>`.
  - Roles and extraction are exactly AT-024's documents: user, agent text, compact tool-use lines; no tool results
    or thinking. Put the extractor in `views/text.rs` so AT-024's projection reuses it (or reuse AT-024's if it
    landed first).
  - `max_chars` defaults to 8,000 (max 32,000), cut at document boundaries.
  - Says "(N earlier — read with before=<seq>)" when cut.
  - Reads go through `app.store.read`, bounded by a seq range, never a whole stream.
- Fake CLI: when started with `--mcp-config`, a prompt containing `MCP:<tool>:<json-args>` makes it `curl` the
  endpoint (URL and token parsed from the config arg). It prints the result as a `tool_result` in a `cc.user` event
  so e2e tests can assert on it.

## Notes

### Spike (CC 2.1.322, real CLI; results also in DESIGN §6)
1. `--mcp-config` with an HTTP server connects next to the user's own MCP servers (init lists it as source
   `dynamic`, status `connected`). Tools are `mcp__atelier__sessions` and `mcp__atelier__read`.
2. `--allowedTools mcp__atelier__sessions,mcp__atelier__read` under `--permission-mode auto`: no permission request.
   CC defers MCP tools behind `ToolSearch`, so the model spends one step selecting them first.
3. A 25 s `tools/call` completes with the default timeout. `MCP_TOOL_TIMEOUT=5000` makes CC return an error result
   after 5 s and carry on. Interrupting during the call returns at once with a rejected tool result and a turn that
   ends `error_during_execution`. **Not measured:** a 10-minute call. AT-030 should set `MCP_TOOL_TIMEOUT` itself
   (the driver controls the process env) rather than rely on the default, and must treat an abandoned HTTP request
   as normal (axum drops the handler future when the connection closes).
4. CC's `SendMessage`/`ListAgents` are present in every session. `--disallowedTools SendMessage,ListAgents` removes
   them. Recommendation: drop them from Atelier sessions in AT-028 (see DESIGN §12), not here: until `send` exists
   they'd be the only messaging, and they bypass the log.
5. `--append-system-prompt` works with stream-json input.

### Done
- `rpc::handle(app, actor, cause, call)`; `Call::agent_allowed` (project.remove, fs.* are user-only);
  `Supervisor::send` takes the actor and cause too.
- `POST /mcp` on the loopback router only (`mcp.rs`); hand-rolled JSON-RPC, no new dependency.
- The supervisor mints a token per process (two v4 UUIDs), maps token → session in memory, and forgets it when the
  process's pump ends. It needs `Supervisor::set_mcp_addr` after the listener binds (`main.rs`; the e2e `boot`).
  Without it agents start with no Atelier tools.
- Driver: `StartSpec.mcp` / `system_append`; `--mcp-config`, `--allowedTools`, one combined `--append-system-prompt`.
- `views/text.rs`: the document extractor AT-024 should reuse (`docs(&Event)`, `Role`, `cap`). It already
  covers titles, and 32 KB / 200-char caps, so AT-024's projection can call it instead of writing its own.
- Tools are a table (`mcp/tools.rs::TOOLS`); the allowed-tool list for the CLI is `ATELIER_TOOL_NAMES` in the
  driver. A new tool is a row in each.

### Things to know
- The token is in the agent's argv (`--mcp-config`), so another local user could read it with `ps`. It is
  loopback-only and dies with the process; a unix socket or a config file would be needed to do better.
- No tool appends events yet, so "events appended by agent tool calls carry `actor = agent:<id>`" is covered at the
  `rpc::handle` level (e2e `calls_made_by_an_agent_are_attributed_to_it_and_limited`); `send`/`spawn` get it free.
- `read` counts "earlier" in conversation events (user messages and assistant events), not in lines.
- `sessions` shows `from <id>` for sessions branched from or sharing another's worktree; there is no spawn parent yet.
- The real-CLI check: two sessions in a scratch repo; the second listed both (itself marked `(you)`) and read the
  first, with no permission request.
