## Context
Mockup step 7 and DESIGN §11.5. An agent asks Atelier to start a child. The child is a full session: visible,
steerable, persistent and in its own workspace. That's unlike CC's `Task` subagents, which are one-off and
invisible. Because it persists, the parent (or anyone) can come back with follow-ups through `send`/`ask`.

Workspaces come from AT-033 (share read-only, branch-from-snapshot). This ticket only exposes them to agents.

Read first: DESIGN §11, AT-033, the mockup's step 7 (`atelier-mockups.html`, "Agents that start agents"), `rpc.rs`
(`SessionCreate`), `workspace.rs` (`prepare`), `views/sessions.rs`, `web/src/ui/Sidebar.tsx`, and the session header.

## Scope
- **Domain**: `SessionCreated` gains `#[serde(default)] parent: Option<SessionId>`. `SessionRow` gains `parent`. The
  sessions projection stores it (bump the version).
- **Workspace** (`workspace` param; all of it is AT-033's machinery):
  - `{ branch: "self" | <id> }`, the default: a new worktree at a snapshot of the parent's (or any session's)
    working tree, uncommitted changes included;
  - `{ share: "self" | <id> }`: read-only in that session's worktree. This is the reviewer case:
    `spawn { task: "review my changes", workspace: { share: "self" } }`;
  - `"fresh"`: a new worktree from the project's HEAD;
  - `"project"`: the project checkout.

  The tool description gives one line of guidance per option.
- **Tool** `spawn { task, title?, workspace?, model?, wait? }`:
  - The child's first message is the task inside an envelope: who spawned it (id, title), its workspace and branch
    (and for a share, that it's read-only), and "report back with send(to=<parent>) when done, or just finish; the
    parent can ask you follow-ups".
  - The review prompt template from AT-033 is offered as a convenience: `spawn { review: "self" }` is shorthand for
    a shared, read-only child with that prompt, which sends its findings to the caller.
  - Returns `{ id }` as text: "started 9c1e 'Write migration 0015' in worktree atelier/…-9c1e".
  - `wait: true` blocks until the child's first turn ends and returns its final text. It shares the
    wait/timeout/deadlock machinery with AT-030; if AT-030 hasn't landed, leave `wait` out and note it.
  - Not pre-allowed: it goes through the permission mode (DESIGN §11.2).
- **Limits** (in `rpc`, from the sessions view; deterministic):
  - depth ≤ 3;
  - ≤ 4 non-archived children that are running or waiting, per parent;
  - configurable in Settings.

  A refusal says which limit was hit and how to raise it.
- **Web**:
  - The sidebar and session lists nest children under their parent (one level of indent per depth, collapsed by
    default when the parent is archived).
  - The session header gets a gold provenance line, *spawned by "<parent title>"*, linking to the parent.
  - In the parent's transcript, the `spawn` tool call renders as a card linking to the child, with its live status
    dot (blue running, red waiting, green idle/done).
  - A child waiting on a permission is red in the inbox like any session. The inbox row says whose child it is.
- Archiving a parent doesn't archive its children. Say so with a hint in the archive confirmation if it has live
  children.

## Notes (as built)
- `wait` is left out: AT-030's wait/timeout machinery hasn't landed. The `send` tool (AT-028) hasn't either, so the
  child's envelope says "report in your final message" until `send` exists in the tool table, then switches to
  "report back with `send`" on its own (`spawn::Envelope::can_send`); `review` does the same.
- Limits are `ATELIER_SPAWN_DEPTH` (3) and `ATELIER_SPAWN_CHILDREN` (4) in the server's environment. There is no
  server-side settings store yet, so the Settings screen doesn't expose them; the refusal names the variable.
  A child that hasn't had its first turn (idle, 0 turns) counts as live, or a burst of spawns would slip past the cap.
- Archive has no confirmation dialog, so the live-children hint is the button's tooltip plus a note after archiving.
- Not done: the real-CLI check (builder `spawn { review: "self" }` → reviewer reports back → re-check). It needs AT-028.
  A collapsed archived parent shows "+N spawned" but has no expand control yet.
