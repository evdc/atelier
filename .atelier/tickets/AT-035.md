## Context
DESIGN §2: authored things (tickets, the board config, later notes and pages) are plain files in `.atelier/`, and
"the server watches `.atelier/`; file changes are appended as events, so the log remains a complete history". None
of that exists yet. This ticket builds the watcher and the event. The tickets board (AT-036–AT-041) is the first
thing built on it, and automations (DESIGN §10.3) will build on it too.

Read first: DESIGN §2, §5, §10.3 (how a ticket drag becomes a signal); `crates/atelier-core/src/domain.rs`,
`stream.rs`; `crates/atelier-store/src/projection.rs`; `crates/atelier-server/src/lib.rs` (`App::with_driver`),
`views/mod.rs`, `views/projects.rs` (a small projection to copy); `rpc.rs` (`project.add`/`project.remove`).

## Goal
Every added project's `<project.path>/.atelier/` is mirrored into its `p/<project>` stream: any create, edit or
delete of a file there, whether by a person, an agent, or `git pull`, appends one `file.changed` event with the
new content. Projections can then fold `.atelier/` without touching the disk.

## Scope
- **Domain** (stream `p/<project>`): `FileChanged { path: String, text: Option<String> }`, kind `file.changed`.
  - `path` is relative to the project root and uses `/` (e.g. `.atelier/tickets/AT-035.md`).
  - `text: None` means the file was deleted.
  - Actor: `atelier` for watcher-observed changes. AT-038 passes `user` when the change came from an RPC.
- **`files` projection** (`views/files.rs`): table `(project, path, hash, len, seq)`. `hash` is a stable 64-bit
  hash of the text, computed in the projection (FNV-1a, about 10 lines, no dependency). Deletes remove the row. No
  view or watch: it exists so the watcher can dedupe, and later for `at://` lookups.
- **Watcher** (`crates/atelier-server/src/files.rs`):
  - `ingest(app, project, rel_path, actor) -> Result<Option<Arc<Event>>>` reads the file and compares it with the
    `files` row. It appends `file.changed` only if the file is new, changed or gone, so repeated FS notifications
    and rescans are no-ops. Serialize ingests per project with a mutex: a watcher event and an RPC write of the same
    file must not both append.
  - **Startup scan**: for each project, walk `.atelier/`, ingest every file, and append deletes for `files` rows
    whose file is gone. This catches edits made while the server was down.
  - **Live**: use the `notify` crate (FSEvents on macOS) with a recursive watch on each project's `.atelier/`
    (create the watch when `.atelier/` appears, too: watch the project root non-recursively for that). Debounce
    about 100 ms per path. Start watching on `project.added` and stop on `project.removed`.
  - **What counts as a file**: regular files only. Skip names starting with `.` and ending in `~`, `.swp`, `.tmp`;
    skip files over 256 KB (log a warning) and non-UTF-8 files.
- Wire it into `App::with_driver` (scan, then watch) and the projections list.

## Design notes
- Store the whole text, not a diff: tickets are a few KB, and projections must be able to fold the latest content
  from the event alone (rule 3: no IO in projections). Blob offload (AT-006) can apply later without changing the
  kind.
- `notify` is a real dependency. It's justified: polling every project's tree would be the jank-prone alternative.
  Note it in the hand-back.
- Only the project directory (the main checkout) is watched. Agents in worktrees that edit a ticket change *their*
  copy, and the board sees it only after the branch is merged. That's correct for now; record it as a follow-up
  rather than watching worktrees.

## Acceptance
- [x] Unit: `files` projection insert, update and delete; hash stability; the skip rules.
- [x] e2e: add a project with `.atelier/tickets/X.md`, and a sub to `p/<project>` sees `file.changed` with its
      text. Edit it and you get one more event (not two). Delete it and you get `text: null`. Restart the server
      with nothing changed and you get no new events. Edit while the server is stopped, and the restart appends
      exactly one event.
- [x] Events from a burst of 20 rapid writes to one file coalesce to a handful, and the last one has the final
      content.
- [x] `make check` and `make test` pass.

## Out of scope

- Interpreting files (AT-036, AT-037), and signals (DESIGN §10.3).
