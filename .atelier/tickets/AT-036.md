## Context
With `file.changed` (AT-035) in the log, tickets can become a server-side view the board watches, the same way
`sessions` is. A ticket is `.atelier/tickets/<ID>.md`: YAML-style front matter, then a markdown body (see
`.atelier/tickets/README.md` and any ticket here). **Status is a free-form string.** Which statuses exist, and in
which order, is project configuration (AT-037), not an enum in code.

Read first: AT-035's code; `views/mod.rs` (the three steps for adding a view); `views/sessions.rs` (scoped view,
`list`/`get`); `crates/atelier-proto/src/lib.rs` (`ViewName`, row types); `web/src/lib/view.ts`.

## Goal
`watch { view: "tickets", scope: <project> }` gives one row per ticket file, kept current as files change.

## Scope
- **Front-matter parser** (`views/frontmatter.rs`, pure): a `---` fenced block at the top of the file, holding
  `key: value` lines.
  - Values can be bare scalars, `"double"`/`'single'` quoted strings, or inline lists `[a, b]`. That's the subset
    our tickets use. Don't add a YAML dependency.
  - Unknown keys are kept in an `extra: BTreeMap<String, String>` so nothing is lost.
  - Return a parse error rather than panicking. A file with no front matter is still a ticket, titled by its first
    `# heading` or else its filename.
- **Projection `tickets`**:
  - Folds `file.changed` for paths matching `.atelier/tickets/*.md`, except `README.md`. Deleted files remove
    their row.
  - Table columns: `key` (= `<project>/<path>`, globally unique as `views::row` needs), `project`, `path`, `id`,
    `title`, `status`, `size`, `milestone`, `area`, `depends` (JSON), `checks_done`, `checks_total` (counts of
    `- [x]` and `- [ ]` in the body), `extra` (JSON), `problem`, `updated_at` (event ts).
  - Report `Change::new("tickets", key, Some(project))`.
- **Identity**: `id` is the filename stem. If the front-matter `id` differs, keep the stem and set `problem`
  (e.g. AT-034.md currently says `id: AT-033`). The board shows that as a quiet warning.
- **Status**: a trimmed string, taken verbatim. A missing status is `""`, which the board treats as "no status"
  (AT-039).
- **Proto**: `TicketRow` (the fields above, minus `extra`, unless the board needs it; keep rows small, and don't
  ship the body) and `ViewName::Tickets` (scope: project id). Add `snapshot`/`row` arms, then run `make gen`.
- **Order**: natural order of `id` (AT-9 before AT-10). Clients reorder per column anyway.

## Acceptance
- [ ] Unit (parser): every ticket currently in `.atelier/tickets/` parses, quoted titles with backticks and colons
      included; lists; missing front matter; unterminated fence → `problem`; CRLF line endings.
- [ ] Unit (projection): create, update, delete; a status change only touches that row; README is ignored; the
      id-mismatch problem.
- [ ] e2e: watch `tickets` for a project, edit a ticket's status on disk, and receive a patch with the new status.
- [ ] Bindings regenerated; `make check` and `make test` pass.
