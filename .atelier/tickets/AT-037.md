## Context
The tickets board needs to know which statuses exist and how they group into columns. Both must stay data, not
code: different projects use different workflows (`open → in-progress → review → done`, or anything else). Per
DESIGN §1 ("plain files for what's authored") the config is a file in the repo, shared through git and editable by
people and agents alike.

Read first: AT-035's code; `views/mod.rs`; `views/projects.rs`; `crates/atelier-proto/src/lib.rs`.

## Goal
A `board` view gives each project's effective board config: the file's contents if it exists and is valid,
otherwise defaults, plus any problem found.

## Scope
- **File**: `.atelier/board.json`. JSON, because serde_json is already here, it round-trips exactly when the UI
  rewrites it (AT-038), and agents edit it reliably. Shape:
  ```json
  {
    "statuses": ["open", "in-progress", "review", "done"],
    "columns": [
      { "title": "To do",  "statuses": ["open"] },
      { "title": "Doing",  "statuses": ["in-progress"] },
      { "title": "Review", "statuses": ["review"] },
      { "title": "Done",   "statuses": ["done"], "collapsed": true }
    ]
  }
  ```
  - `statuses` is the ordered list of known statuses (what a status picker offers).
  - A column shows tickets whose status is in its `statuses`. Dropping a ticket into a column sets the column's
    **first** status.
  - `collapsed` (optional) renders the column narrow by default.
  - Unknown fields are kept, so a newer client's additions survive.
- **Defaults** (no file): statuses `open`, `in-progress`, `done` (what `.atelier/tickets/README.md` documents),
  one column per status.
- **Validation** (lenient: show the board anyway):
  - a column with no statuses is dropped;
  - a status used by a column but missing from `statuses` is appended to it;
  - a status in two columns stays only in the first;
  - invalid JSON falls back to the defaults.
  Each fix adds a line to `problems: Vec<String>`.
- **Projection `board`**:
  - Folds `file.changed` for `.atelier/board.json` (and its deletion).
  - Table `(project PRIMARY KEY, config JSON, problems JSON)`.
  - Projects with no file have no row. The query returns the defaults for them, so `row`/`snapshot` always yield
    exactly one row per scope.
- **Proto**: `BoardConfig { statuses: Vec<String>, columns: Vec<BoardColumn> }`,
  `BoardColumn { title, statuses, collapsed: bool }`, `BoardRow { id: <project>, config, problems,
  from_file: bool }`, and `ViewName::Board` (scope: project). Run `make gen`.
- Put validation and defaults in a pure function, `board::effective(raw: Option<&str>) -> (BoardConfig,
  Vec<String>)`. AT-038 reuses it to validate writes.
