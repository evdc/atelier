## Context
Dragging a card (AT-040) and editing columns (AT-041) must change files, because the files are the truth. DESIGN
§10.3 spells out the flow: the UI sends `ticket.update { status }`; the call rewrites the ticket's front matter;
the change is appended as `file.changed`; the tickets projection folds it. An agent that edits the file directly
produces the same result.

Read first: AT-035 (`files::ingest`), AT-036 (front-matter parser), AT-037 (`board::effective`); `rpc.rs`
(`handle`, `agent_allowed`); `crates/atelier-proto/src/lib.rs` (`Call`).

## Scope
- **`ticket.update { project, ticket, status, expect? }`**:
  - `ticket` is the id (the filename stem). `expect` is the status the client last saw.
  - Read `.atelier/tickets/<ticket>.md` from the project directory.
  - If `expect` is given and differs from the file's current status, refuse: "AT-012 is now *review*
    (changed elsewhere)". The client reverts its optimistic move.
  - Rewrite **only the `status:` line** of the front matter. If it's missing, insert one after `title:` (or at
    the end of the front matter). Every other byte stays as it was, so diffs stay one line.
  - Write atomically (temp file in the same dir, then rename). Then call `files::ingest(.., Actor::User)` so the
    event lands now, attributed to the person, rather than whenever FS notifications arrive (the watcher then
    dedupes).
  - Any non-empty status is accepted, even one not in the board config: the config is advice, not a schema.
    Reject newlines and `:`-leading values.
  - Agents are allowed. This is what an agent should call to move its own ticket.
- **`board.update { project, config }`** (`config: BoardConfig`):
  - Validate with `board::effective`. Refuse if it reports problems, so the UI shows them rather than writing a
    half-fixed file.
  - Merge into the existing file's JSON so unknown fields survive. Write it pretty-printed (2-space indent,
    trailing newline) and atomically, creating `.atelier/` if needed, then ingest as above.
  - Person-only (`agent_allowed` false): agents edit the file directly if asked.
- Both return `null`. State arrives via the `tickets`/`board` watches (rule: RPCs never return state).

## Out of scope
- Creating, renaming or deleting tickets; editing other front-matter fields (worth a follow-up:
  `ticket.update` could take a small patch map later, as an optional field).
- Committing to git. Writes leave the working tree dirty, like an editor would. Note in the hand-back whether
  that's annoying in practice.
