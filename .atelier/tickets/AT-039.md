## Context
The `tickets` and `board` views (AT-036, AT-037) give the rows and the column layout. This ticket draws the board
as a project view next to Sessions. Dragging (AT-040) and editing columns (AT-041) come after, so keep the
pieces they need (column/card components, a pure grouping function) separate and reusable.

Read first: `CLAUDE.md` rules 4 and 5; `web/src/lib/routes.ts` + `routes.test.ts`, `router.ts`;
`web/src/ui/Sidebar.tsx` ("Views" group); `SessionsView.tsx` (view layout, `createView`); `web/src/lib/view.ts`;
`web/src/styles/tokens.css`, `app.css`; the tickets mockup in `atelier-mockups.html` (step 1, `/* tickets */`
styles).

## Scope
- **Route**: `#/p/<project>/tickets` → `{ name: "tickets", project }`. Add it to `parse`/`href`, with tests, and a
  "Tickets" item with a count under the sidebar's "Views". On a phone, reach it from the project screen. It needn't
  get a bottom tab.
- **Grouping** (`web/src/lib/board.ts`, pure, vitest):
  `columns(config, tickets) → { title, status (drop target), tickets[] }[]`.
  - Tickets go to the column containing their status.
  - Tickets whose status is in no column go into a trailing **"Other"** column, shown only when non-empty. No
    config can hide a ticket.
  - Tickets with empty status go into the first column.
  - Within a column, order by natural id.
- **Board UI** (`web/src/ui/TicketsView.tsx`, `ui/board/`):
  - Columns side by side, scrolling horizontally. Each column scrolls vertically on its own. The heading is the
    title (IM Fell) plus a count. `collapsed` columns render as a narrow vertical strip that expands on click (the
    choice lasts while the view is open).
  - A card shows: id (mono), title, small meta (size, area, `checks_done/checks_total` if any), and `depends` ids.
    If the card's status isn't its column's first status (e.g. a column holding `review` and `qa`), show the
    status as a small label. If the ticket has a `problem`, show a gold mark with the problem as its title text.
  - Clicking a card does nothing yet (there's no ticket detail view; that's a follow-up). Where `canOpenIn()` is
    true, offer "Open in editor" on the card (`openIn("editor", <project.path>/<path>)`).
  - If the board config has `problems`, show a gold note above the board listing them.
  - Empty state when the project has no tickets: one line saying where tickets live (`.atelier/tickets/*.md`).
- **Style**: parchment cards with hairline borders, no shadows. Colour only from tokens: the column for
  in-progress-like work needn't be blue. Columns are neutral; colour is reserved for meaning (gold = notice).
  Check light and dark.
- **Phone**: columns become one column at a time, with a horizontal scroll-snap and the column titles as a
  segmented header.

## Performance
- Watch `tickets` and `board` scoped to the project only while the view is open.
- Cards are keyed by row identity (`createView` reconciles), so a status change re-renders one card in two
  columns, not the board.
- No virtualization needed under ~300 cards per column. Say so in a comment and in the hand-back if you measure.
