## Context
Moving a card to another column sets the ticket's status to that column's first status, through `ticket.update`
(AT-038), which rewrites the file. This is also the trigger DESIGN §10 builds on ("dragging a ticket to Doing
starts a session on it"), so it has to be reliable and feel instant.

Read first: AT-038's `ticket.update` (`expect` semantics); AT-039's `TicketsView`, `ui/board/`, `lib/board.ts`;
`web/src/lib/conn.ts` (`call`); `CLAUDE.md` rule 4.

## Scope
- **Pointer-based drag** (`web/src/lib/drag.ts` + the board):
  - No library, and not HTML5 drag-and-drop: its ghost image and touch support are poor, especially in the iOS
    WebView.
  - Use pointer events with `setPointerCapture`. A drag starts after 4 px of movement with a mouse, or after a
    ~250 ms long-press with touch, so scrolling a column still works.
  - While dragging, the card's placeholder stays in place, dimmed. A lifted copy follows the pointer via
    `transform` only, updated once per animation frame. Measure column rects once at drag start, and hit-test
    against them, not the DOM, on each frame.
  - The column under the pointer gets a hairline highlight (ink, not colour).
  - Auto-scroll the board horizontally near its edges. Escape cancels.
  - Dropping on the card's own column, or outside any column, is a no-op.
- **Optimistic move**:
  - On drop, show the card in the target column at once. Keep an overlay of pending moves
    (`ticket id → status`) that `columns()` applies on top of the rows. Make it a pure function and test it.
  - Call `ticket.update { status: column's first status, expect: the status the card had }`.
  - On success, clear the overlay entry when the row's status matches, which happens when the watch patch arrives.
  - On error, drop the overlay entry (the card snaps back) and show the server's message briefly near the board
    header in red.
  - Dropping into "Other" is not allowed (it has no status).
- **Without a pointer** (accessibility and phone):
  - Each card has a "Move to…" menu, reachable by keyboard (Enter/Space on a focused card), listing the columns.
    It uses the same optimistic path.
  - On a phone, where one column shows at a time (AT-039), long-press opens this menu instead of dragging.

## Acceptance
- [ ] vitest: the overlay fold (pending → confirmed → cleared; error → reverted; a newer remote change wins); the
      drag threshold/long-press state machine as a pure reducer.
- [ ] Manual: dragging between columns is smooth on a 60-card board (no dropped frames in the Performance panel
      during a drag), and the file on disk changes by one line.
- [ ] Manual: editing the same ticket's status in an editor while a drag is in flight results in a refusal and a
      snap-back, not a silent overwrite.
- [ ] Keyboard-only move works; the phone long-press menu works.
- [ ] `make check` and `make test` pass.

## Out of scope
- Reordering within a column. That needs a persisted rank, and writing a `rank:` into every file on each drag
  churns git. Follow-up: decide between a rank in front matter, an order list in `board.json`, or a sort option
  per column.
- Multi-select drag, and dragging columns themselves (AT-041 reorders columns).
